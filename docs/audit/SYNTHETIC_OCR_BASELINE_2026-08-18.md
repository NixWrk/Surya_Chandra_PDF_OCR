# Synthetic real-engine OCR baseline — 2026-08-18

Status: accepted as two immutable synthetic measurement checkpoints covering all
nine corpus fixtures at least once. They measure accuracy, retention, page
mapping, and stage timing, but are not a production accuracy acceptance gate.
The first record preserves one artifact assembly failure as observed; the
failure was fixed later and verified without rerunning OCR.

This baseline does not authorize a Surya/Chandra upgrade or OCR-policy change by
itself. It is a comparison point for controlled experiments.

## Observed blank/graphics failure and fix

Both engines and page reconciliation completed `blank-graphics` correctly:
page 1 was `both_verified_blank`, and page 2 was accepted as explicit non-text
graphics. Final artifact assembly nevertheless rejected the document with:

```text
Output PDF has empty extracted text layer.
```

The cause was an artifact-side authorization mismatch: the builder consumed
`accepted_textless_graphics_pages` but ignored the separately sealed
`both_verified_blank` page. It therefore authorized page 2 but not page 1.

The defect was handled test-first:

- `eaa3a79` — three RED tests for valid mixed/all-blank evidence and forged
  nonblank pixels;
- `253bca0` — accept only verified-blank pages whose reconciliation row,
  engine rows, geometry, owned raster path, size, SHA-256, dimensions, pixel
  SHA-256, and recomputed blank-pixel classification agree.

Verification after the fix:

```text
tests/test_ocr_artifact_searchable.py: 95 passed
full suite: 676 passed, 9 skipped, 5 warnings in 243.44s
```

The preserved failed run was rebuilt artifact-only in Docker with
`--network none`; engines and models were not run again. Result: `ok`, 2 pages,
251,250 bytes, SHA-256
`5842f2d1fe1356b6eb0bf0b91d284281a2ee6a47d57ebcb7af71a9d82029f49b`.
The local evidence is under
`outputs/audit_synthetic_baseline/v1_0_1/postfix-blank-graphics/`.

An initial `clean-en` pilot omitted required `UNISCAN_GPU_DEVICE_ID` and stopped
before either engine ran. It is excluded from metrics; its diagnostic log is
retained at
`outputs/audit_synthetic_baseline/v1_0_1/logs/clean-en-runner-missing-gpu.log`.

## Offline Docker source rebuild

A no-cache source-layer rebuild was performed on top of the existing pinned
local image with build network disabled. Both Surya and Chandra venvs installed
the current `uniscan` source without dependencies, imported PyTorch
`2.11.0+cu126`, the CLI help command passed, and the artifact-only

This is partial new-PC evidence only. It proves that the current source packages
and runs on the preserved image without downloads; it does not prove a clean
base-image, OS-package, Python-dependency, CUDA, or model-cache installation.

## Storage scope decision

No global document registry or permanent history of every processed PDF will be
introduced. Run identity, chunk hashes, and configuration metadata belong only
to a specific active/resumable cache or retained result. They prevent a chunk
from one file or runtime from being reused for another; they are not a user
document catalog.

HTTP successful run/chunk working data is removed by default unless
`UNISCAN_KEEP_JOB_RUNS=1`. Terminal job metadata/results use the existing
retention policy: 30 days for success and 90 days for failure by default, with
per-job TTL support. Persistent benchmark/resume caches remain explicit. A
bounded age-and-size quota for those explicit caches is still required; cleanup
must never follow links or delete user source PDFs.

## Remaining measurement gaps

- Repeat runs are still required for median and tail latency.
- Peak VRAM and peak process RAM were not captured consistently.
- Clean dependency resolution and cold model-cache provisioning remain untested.
- Procedural rotation, low-contrast/noise/skew/low-resolution, native-text, and
  long-document cases now have real-engine runs. Representative raster scans and
  denser mixed-language/layout cases still need reviewed Ground Truth.
- `mixed-layout` requires controlled experiments and human/layout review.
- The historical private exact-retention root cause remains unproven because its
  rejected candidate was not preserved.
